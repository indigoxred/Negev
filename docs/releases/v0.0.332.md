# v0.0.332

Fixes account deletion in v0.0.331, which could hand a deleted person's kept requests to the next account created. Update from v0.0.331 promptly.

**Account deletion fix.**
- In v0.0.331, SQLite gave the highest freed ID to the next new row. Deleting the newest account let the next registration take that account's ID, so requests kept as history (their download had started) appeared as the new person's. Deleted request IDs were reused the same way.
- Accounts, requests and download attempts now get IDs from a durable counter (`durable_id_counters`) that never goes back, even after rows are deleted. On first use after upgrading, the account counter also covers IDs still referenced by kept requests, pending titles and parent-show watches, including any left by a v0.0.331 deletion.
- Deletion now removes download attempts that never reached qBittorrent. If a download is still being prepared or reconciled, deletion is refused until it settles.
- Used invitations stay listed after their creator is deleted, now with no creator name. The invitations table is rebuilt once so its `created_by` column can be empty. No columns are removed.

**Check for data affected by v0.0.331.** This only applies if you deleted an account on v0.0.331 and someone registered afterwards. This read-only query lists requests that are older than the account that now owns them:

```sql
SELECT r.id, r.requester_id, u.username, r.created_ms, u.created_ms AS account_created_ms
FROM requests r JOIN users u ON u.id = r.requester_id
WHERE u.created_ms > r.created_ms;
```

An empty result means nothing moved. This release does not reassign rows that already moved.

**Disabled accounts pause.** A disabled account's requests are not searched, and no download is reserved or started for them. They resume when the account is enabled again. A download already in qBittorrent finishes normally. A pause is retried rather than sent to review.

**Logs.** About 160 places in the download, availability and identity code that turn an error into a held-and-retry result now log the underlying error. Each entry is JSON on stderr at warn level, with secrets redacted, at most once per error every 10 minutes. `NEGEV_LOG_LEVEL=error` or `silent` turns these off.

**Other changes.**
- The README has a quick start and a table of every setting.
- The Shoko recent and Plex index schedulers use the shared timer loop. A second start no longer changes what the Shoko recent scheduler runs next.
- Compression negotiation follows the browser's preference weights and refusals (RFC 9110). If no acceptable encoding remains, the server answers 406.
- `consumer.css` and `style.css` have one declaration per line. Only whitespace changed.
- Removed three scheduler modules that the server never used.

**Upgrade and rollback.**
- New table: `durable_id_counters`. Earlier builds ignore it.
- `invitations.created_by` can now be empty. Earlier builds still read and write the table.
- Rolling back to v0.0.331 brings the ID reuse bug back, so roll back to v0.0.330 instead if needed.
- The install example stays pinned to v0.0.330, because v0.0.331 has the deletion bug.
