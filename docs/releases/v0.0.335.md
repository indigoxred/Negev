# v0.0.335

Closes four workflow gaps found by code review, regression tests and controlled Shoko 6 event tests.

- Shoko 6 detection and hash events use managed-folder-relative paths with a leading slash. Negev now accepts that single prefix consistently with exact file observations. Folder boundaries, length limits and rejection of traversal, repeated separators and control characters remain enforced.
- Inventory reconciliation makes bounded progress after bulk removal instead of repeatedly holding without withdrawing any stale observations. It still requires matching complete inventories, retires at most 100 observations per batch, protects newer targeted reads and keeps full reconciliation blocked while overflow remains. Existing daily overflow pacing is unchanged.
- Background session checks update acquisition capabilities and the service notice without resetting typed work or the selected detail.
- Admin reads and delayed mutation callbacks cannot overwrite a later session or a newer refresh. Permission changes invalidate previously loaded account settings. Existing one-time invite/reset link protections remain.
- The pure-publish test fixture resolves its directory before constructing paths, avoiding Windows path-casing differences while retaining its file identity and content assertions.

The [workflow verification record](../workflow-verification.md) distinguishes observed integration behavior from simulated tests and remaining acceptance gaps. No schema migration or dependency change is introduced. Preserve a matched database/credentials/configuration backup and the v0.0.334 image before updating.
