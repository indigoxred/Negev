# v0.0.333

Repairs request preparation, account-link handling, filtered search and inventory progress, and separates the browser entry point into controllers without changing its intended behavior.

- Pending titles resume after their account is re-enabled. Startup also recovers historical preparations closed specifically because account access changed, when they have no newer replacement or existing normal request. Cancelled and resolved preparations stay closed.
- Invitation creation refreshes the invitation list. Consumed invitation/reset links do not reappear after sign-out.
- Filtered search keeps its page counts consistent. When restricted-title access is off, unverified search results remain ID-only until their metadata is confirmed; old-session reads cannot populate a new session's cache.
- A failed score write cannot crash the service, and an over-linked Shoko file cannot stall inventory progress.
- Legacy-published import folders remain readable by Shoko. Existing watch access checks from the reviewed fixes are retained; the remaining 18+ work is deferred.
- Authentication, tracking preferences, browse/search pages, session transitions and detail/request components now have separate browser modules. The entry point retains routing and page-level handler order.
- The pipeline and feed supervisor retain their existing scheduling models. New characterization tests cover their single-timer, recovery, wake, deadline and shutdown behavior.
- The Windows ED2K fixture now observes a distinct change time before testing same-size/restored-mtime edits. Production hashing guards are unchanged; CI repeats the Windows safety tests.
