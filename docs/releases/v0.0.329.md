# v0.0.329

Temporary outages no longer park downloads and imports in permanent review, and admins can now retry or release a parked item from the review page.

**Retries.** A start check that failed because Plex, Sonarr, qBittorrent, a mount or the worker was briefly unavailable now backs off (30 min, 1 h, 2 h, 4 h, then every 6 h) instead of going to review after any earlier retry. Before, such an attempt kept its episode claims, so no other release of those episodes could be chosen. A publish staging check that runs before any file is read now retries like the mount check. Publish retry limits that can mean rehashing a batch count holds for the same reason, not every claim. Rows that earlier builds parked for these reasons get another turn when the queue opens, and each is logged so it can be undone exactly (`docs/stage-hold-policy.md`).

**Admin actions.** On the review page, **Retry now** re-runs a parked start or import check through all its normal gates. **Release download** applies to a download that never started. It removes the stopped torrent from qBittorrent without deleting files, proves the staging folder is empty, retires the attempt as a policy reset and frees its episodes. Every action is logged with the admin's user ID.

**Fixes.**
- Re-running restart recovery no longer overwrites a request search that is still running.
- One bonus file with a plan conflict no longer blocks every other bonus.
- An invalid download-progress snapshot no longer leaves a completion check stuck until restart.

**Internal.**
- Queue retry rules are in one shared module.
- The "live attempt" check is defined once.
- Admin routes moved to their own module.
- The release dialog was reformatted.
- A new test checks that reopening the service changes no schema or data (`docs/schema-changes.md`).

**Upgrade and rollback.**
- Schema changes are additive only: the tables `stage_hold_policy_revivals` and `operator_review_actions`, and the publish columns `last_reason` and `reason_run`. Earlier builds ignore them.
- The install example now pins v0.0.328. Catch-up index of changes since v0.0.268: `docs/releases/v0.0.269-v0.0.328.md`.
